Computer Vision

SegFormer with Siamese Cross-Attention: template separation for centimeter-level defect generalization

The problem: Existing SegFormer model worked well on existing templates but triggered false positives on new templates. Mitigation needed finetuning on every new template; not scalable. Root cause: a single encoder cannot distinguish defect pattern on known template from new template structure.

The solution is threefold:

Rearchitect to Siamese: Separate encoders (template and target) using pre-trained weights. Cross-Attention Fusion: Feature-level attention forces the network to learn template-defect distinctions explicitly. Representation Learning: Inductive bias from Siamese structure teaches invariants, not memorization.

Architectural separation is an inductive bias. The network learns structural distinctions (what makes a defect) rather than memorizing appearances. New templates generalize because the learned boundary is invariant.

Result
Generalization to unseen templates without retraining. The icing: 8% F1 improvement on existing templates!

Systems Architecture

A case for Zenoh: unified query-response and pub-sub on one transport

Problem: Building distributed systems requires choosing between RabbitMQ (mature pub-sub, awkward query-response), gRPC (clean RPC, pub-sub as an afterthought), or REST+polling (simple but chatty). Each solves one pattern well; none unifies both.

Solution: Zenoh unifies queries (RPC) and subscriptions (pub-sub) on one transport. The architecture is simple: stateless API gateways forward every HTTP request as a Zenoh query to the master; event subscriptions are native. No connection pooling, no session management, no coordination overhead.

Real use case: I chose Zenoh in a distributed camera system with 100+ heterogeneous camera nodes, stateless gateways, and a master registry. Obtained: instant gateway scaling, transparent router recovery, zero coordination overhead.

Pattern
Stateless gateway + unified queries and subscriptions over one transport layer.
Tradeoff
Smaller ecosystem than MQTT/RabbitMQ, no event log (not a Kafka replacement); excellent fit for request-response + events with automatic resilience.

Data Analysis

Measuring geopolitical shift: 19.5 million news articles, PySpark pipeline, alignment classification

Pipeline: Extracted 19.5 million GDELT events from GDELT Global Knowledge Graph via BigQuery, processed with PySpark to compute bilateral Goldstein alignment scores (conflict-cooperation scale -10 to +10). Normalized per-period, applied 33rd percentile threshold for binary classification (Pro-Ukraine / Neutral / Pro-Russia), and visualized geospatial shift across 215+ countries.

Finding: Western Europe's alignment reversed within one year. Countries appearing pro-Russia in 2021 due to energy/trade ties (Germany: -9,811 total Goldstein, France: -10,613) flipped decisively pro-Ukraine by 2022-2024 (Germany: +292,279, France: +154,737). The shift is statistically sharp, not gradual; a historical inflection point visible in global media discourse.

Teamwork with AI

Directing with clarity: how teams move 10x faster without breaking systems

The problem: AI gives teams tremendous speed. But speed without clarity breaks systems; when every engineer can ship in hours instead of days, components collide if boundaries aren't crystal clear.

Three patterns that work:

Requirements: document system constraints upfront (throughput, latency, state ownership, recovery targets). Pin it in your chat; you'll refer to it constantly when validating frameworks and debugging.

Contracts: define API specs and error cases before building; everyone develops against it. A message queue looked perfect until validation flagged a concurrency issue that broke the contract.

Validate: ask the AI to map the relevant subset from requirements and contracts, then validate the framework against both. When the system went live, it fitted on the first try; not because the AI was perfect, but because teammates trusted the contract and I owned the failures.

Insight
Speed without clarity breaks trust. AI gives you the speed; you have to give the clarity. Requirements. Validation. Contracts. That's how teams move 10x faster without falling apart.

First Principles

Start from the problem, not the symptom. What makes this a problem? Is it a scaling issue, a generalization failure, or a coordination bottleneck? The diagnosis shapes the solution.

Understand the constraint. Is this UI work (users first), ML work (metric vs. compute), or systems work (latency vs. throughput)? The audience and the tradeoff space matter.

Document as you build. Contracts, requirements, design choices, not as an afterthought, but as the backbone of the work.
