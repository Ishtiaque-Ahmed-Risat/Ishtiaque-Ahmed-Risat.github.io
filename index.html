Computer Vision

Defects Are Differences

Instead of memorizing every template, the model now compares against it.

The problem: A production SegFormer model segmented defects with centimeter-level precision on a finite set of template objects. Still, every new template brought into the system meant false positives and another round of fine-tuning.

The diagnosis: A single encoder has to learn two things at once: what each template looks like, and what a defect looks like. Faced with an unseen template, it confuses the first with the second.

The fix: Since the templates are known, give the model the reference instead of asking it to memorize one. In a Siamese setup, two SegFormer encoders, both starting from pre-trained weights, embed the template and the target, and cross-attention fuses their features before decoding. The architecture now encodes the right inductive bias: a defect is whatever differs from the template. Template features are computed once and cached, so inference still takes a single pass.

Result
New templates work without fine-tuning. The icing we never asked for: F1 on existing templates rose 9% from a baseline of 79%.

Systems Architecture

Centralized Now, Peer to Peer Later

Ship the simple version first, on a transport that won't lock you into it.

The problem: A fleet of 100+ heterogeneous cameras needed two kinds of traffic: commands to a specific camera that expect an answer, and status updates streaming back. Version one would be centralized, because that is faster to build. The plan: let the cameras collectively do the controller's job.

The choice: NATS and MQTT both need a central server. DDS runs peer to peer but treats request-response as an add-on. Zenoh does both natively and runs peer to peer by configuration, so decentralizing later changes the deployment, not the camera code. The cost: fewer libraries and tools than MQTT.

The design: Built in Python. Stateless HTTP gateways turn each request into a Zenoh query to the controller, which keeps the camera registry and queries the right camera. Cameras publish status, and the controller subscribes. With no state in the gateways, scaling them means starting another one. Cameras own their state, so a restarted controller rebuilds its registry by querying them.

Tradeoff
Every request passes through the controller, making it a single point of failure for now: the price of shipping centralized first, and the part Zenoh lets us remove.

Data Analysis

Talk Is Cheap, Show Me the Deeds

Two-thirds of the help went to Ukraine. Half the world still did business with Russia.

The question: Who did the world actually help? Every country had something to say about the war, so I followed the deeds: 19.5 million GDELT news events, filtered down to the trade deals and aid shipments that went to Russia or Ukraine.

The finding: The total and the countries tell different stories. A few big donors move the total. The map shows everyone else.

The outliers: Hungary, the EU's loudest sceptic, sent most of its help to Ukraine. Serbia, which never sanctioned Russia, split down the middle. Finland talks about Russia but helps Ukraine. China and India kept doing business with Moscow.

Teamwork with AI

Unstoppable Pace, Immovable Seams

AI let everyone ship in hours. What kept the pieces fitting was the one thing that didn't move.

The problem: In my last few projects, each of us, human or agent, could build a component in hours. Writing code stopped being the hard part. Keeping the pieces fitting together while all of them changed at once became the hard part.

What worked for me, in three parts:

Boundaries: Before any code, I documented the requirements and the architecture, down to what each component owns and must guarantee (throughput, latency, ordering, recovery). No new framework got in until a coding agent had trialed it against them.

Handshakes: for every connection, a short contract: who sends, who receives, what can fail, and one concrete example. The example matters most. It gives a teammate, or a coding agent, enough context to build their side alone.

Testing against both: we weren't shy about stubbing the other side, because every stub came from the handshake. A monorepo kept each handshake and both of its sides together, so changing it broke both sides' tests in the same pull request.

Where it paid off: In an IoT gateway, four of us built nine services from edge to cloud. Devices reboot, so one handshake promised that registering twice is safe. The registry, built in an afternoon, rejected repeats with 409 Conflict, and a rebooted device would have read that as failure. A test against the handshake caught it before any device went dark. Now a repeat returns the existing record.

Here is that handshake, in the exact format we used:

Handshake Device registration (POST /api/v1/devices)
From Edge device
To Device registry
Promise Registering twice is safe (idempotent by device_id)
Request register_request.json
Response register_response.json
Test The same registration sent twice: both succeed, one record
Takeaway
Fast teams don't collide in the code. They collide at the seams, so the seams land in the repo before the code does.

Notes to Self

Know why it works, not just why it broke. A success you can't explain is luck, and luck doesn't repeat.

Make the trade, then write it down. Name the price before paying it. When a decision gets reversed, keep it, linked to the one that replaced it, so nobody walks back into the old mistake.

Build the 20% that matters, then step back. Pick the next 20% and repeat. Every round ends somewhere worth stopping, so a deadline decides how much ships, never whether it does.
